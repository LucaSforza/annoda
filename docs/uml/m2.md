# M2 identity, sync and notification UML

Normative contracts established before code. Delivery status: [progress](../progress.md). Portable Rust mechanisms are milestone targets; Keychain/Keystore and OS schedulers are planned host integrations. No diagram asserts background launch timing.

## Identity ownership

```mermaid
classDiagram
    class AccountKeyStore {
        <<interface>>
        +create(authorization) UnlockedAccount
        +unlock(authorization) UnlockedAccount
    }
    class PortableAccountVault {
        -Path directory
        +create(passphrase) UnlockedAccount
        +unlock(passphrase) UnlockedAccount
    }
    class VaultEnvelope {
        +u16 version
        +KdfParameters parameters
        +bytes16 salt
        +bytes24 nonce
        +bytes ciphertext
    }
    class UnlockedAccount {
        -DeviceKeyPair keys
        -FileLock lock
        +identity() DeviceKeyPair
        +lock() void
    }
    class DeviceKeyPair {
        -bytes32 signing_secret
        -bytes32 hpke_secret
        +profile_id() ProfileId
    }
    class NodeIdentityStore {
        -Path private_directory
        -String initialized_peer_id
        +open() NodeIdentityLease
        +replace(expected_peer_id) Result
    }
    class NodeIdentityLease {
        -TransportKeyPair key
        -FileLock lock
        +peer_id() String
    }
    PortableAccountVault ..|> AccountKeyStore
    PortableAccountVault "1" --> "0..1" VaultEnvelope : encrypted disk record
    AccountKeyStore ..> UnlockedAccount : returns after authorization
    UnlockedAccount "1" *-- "0..1" DeviceKeyPair : absent when locked
    NodeIdentityStore ..> NodeIdentityLease : operator protected
    NodeIdentityLease "1" *-- "1" TransportKeyPair
```

Mapping: core key_store trait/structs and identity::DeviceKeyPair; network node_identity store/lease and libp2p keypair. VaultEnvelope serializes only authenticated ciphertext/header, never Debug secrets. UnlockedAccount owns exclusive key-store lock. NodeIdentityLease is separate, filesystem protected plaintext. [Key invariants](../key-management.md): no open→create fallback, stable account/public keys and PeerId, no raw key ABI.

## Bounded synchronization

```mermaid
classDiagram
    class SyncContext {
        +VerifiedCredential credential
        +TrustedIssuers issuers
        +List known_peers
        +Path state_path
        +Path transport_data_dir
        +ContributionInputs contribution
    }
    class SyncBudget {
        +Duration max_duration
        +u64 max_download_bytes
        +u64 max_upload_bytes
        +u16 max_peers
        +u16 max_mailbox_items
        +u16 max_concurrent_requests
        +u16 retries
        +Duration request_timeout
    }
    class SyncService {
        +sync_once(account, context, budget, cancellation) SyncReport
    }
    class AccountHandle {
        -UnlockedAccount account
        -LifecycleGate lifecycle
        +start_sync_session(request) SyncSession
        +lock() Result
    }
    class SyncSession {
        -CancellationToken cancellation
        -OptionalResult result
        +cancel() void
        +wait_result(timeout_ms) OptionalReport
        +is_finished() bool
    }
    class TransferMeter {
        -u64 downloaded
        -u64 uploaded
        +read_remaining() u64
        +write_remaining() u64
    }
    class CancellationToken {
        +cancel() void
        +is_cancelled() bool
    }
    class SyncReport {
        +SyncStatus status
        +u32 verified_items
        +u32 rejected_items
        +u64 downloaded_bytes
        +u64 uploaded_bytes
        +List new_events
    }
    class PeerContributionPolicy {
        +bool enabled
        +bool wifi_only
        +bool charging_only
        +u64 max_storage_bytes
        +u64 max_transfer_bytes
        +Duration max_duration
    }
    class SessionSwarm {
        +connect(allowed_peer) Result
        +poll_page() MailboxPage
        +shutdown() Result
    }
    SyncService ..> SyncContext
    SyncService ..> UnlockedAccount : borrows authorized keys
    SyncService ..> SyncBudget
    SyncService "1" *-- "1" SessionSwarm
    SessionSwarm "1" *-- "1" TransferMeter
    SyncService ..> CancellationToken : observes across awaits
    SyncContext "1" --> "1" PeerContributionPolicy
    SyncService ..> SyncReport : finite result
    AccountHandle "1" *-- "0..1" UnlockedAccount : released after drain
    AccountHandle "1" --> "0..1" SyncSession : active session
    SyncSession ..> SyncService : finite runtime task
```

Mapping: network::sync function/types (SyncService is the module-level operation), raw transport I/O wrapper/meter, existing PeerNode/SQLite; mobile-ffi AccountHandle and SyncSession own native lifecycle. Initial scheduling may be serial, always below requested concurrency ceiling. Invariants: global byte and peer ceilings, outbound-only Annoda RPC admission, no transaction across await, no optional transfers without policy, no swarm after result. Replica batches have distinct owners; a confirmation counts one peer's complete manifest, with Partial for incomplete requested contribution. Start and lock exclude each other; completion follows release of the worker's key reference. Host grant is external and can end at any time. [Lifecycle authority](../background-sync.md).

## Sequence 1: First account creation and secure storage

Rust portable vault target. Native protection adapters planned.

```mermaid
sequenceDiagram
    participant Host
    participant Vault as AccountKeyStore
    participant Crypto
    participant Disk
    Host->>Vault: Explicit create with authorization
    Vault->>Disk: Acquire exclusive private-directory lock
    alt account already exists or inaccessible
        Disk-->>Vault: Typed failure
        Vault-->>Host: No new identity
    else absent and authorized
        Vault->>Crypto: OS-random signing and HPKE keys, salt, nonce
        Crypto->>Crypto: Argon2id and purpose-bound AEAD
        Crypto-->>Vault: Ciphertext envelope only
        Vault->>Disk: Private temp write, fsync, non-clobber publish, directory fsync
        Vault-->>Host: Unlocked account with public summary
    end
```

## Sequence 2: Restore after complete process restart

Rust target includes fresh process proof. Credential renewal is not implicit.

```mermaid
sequenceDiagram
    participant OldProcess
    participant Disk
    participant NewProcess
    participant Vault
    OldProcess->>Disk: Encrypted key vault already durable
    OldProcess->>OldProcess: Terminate and release all key objects
    NewProcess->>Vault: Explicit unlock existing account
    Vault->>Disk: Lock, bound and parse existing encrypted envelope
    alt wrong passphrase, corruption or incompatible format
        Vault-->>NewProcess: Typed error, never regenerate
    else authenticated envelope
        Vault->>Vault: Restore exact signing and HPKE private bytes
        Vault-->>NewProcess: Same public keys and ProfileId
        NewProcess->>NewProcess: Verify old credential under normal expiry/revocation
    end
```

## Sequence 3: OS-triggered finite P2P synchronization

OS scheduler planned host adapter, actual service Rust target.

```mermaid
sequenceDiagram
    participant OS
    participant Host
    participant Vault
    participant Sync
    participant Peer
    participant DB
    OS->>Host: Opportunistic execution window
    Host->>Vault: Authorized open existing account
    alt unavailable locked keys
        Vault-->>Host: Deferred, no account replacement
    else available keys
        Host->>Sync: Same sync_once used in foreground, budget, cancellation
        Sync->>DB: Load persisted progress
        Sync->>Peer: Bounded allowed connections and signed paged poll
        alt no reachable peers
            Sync->>Sync: Deferred report without spin
        else pages available
            Peer-->>Sync: Opaque parcels under transport byte caps
            Sync->>Sync: Verify, decrypt, validate
            Sync->>DB: Short atomic item/state/event/checkpoint commit
        end
        Sync->>Peer: Close all session connections
        Sync-->>Host: Structured report, no notification display claim
        Host-->>OS: Complete task and optionally request another window
    end
```

## Sequence 4: Offline like and local notification event

Rust outbox and network target, actual OS notification display planned.

```mermaid
    end
```

## Sequence 5: Voluntary cooperation in temporary window

M2 target forwards existing authorized replicas. Inbound mobile provider mode planned.

```mermaid
sequenceDiagram
    participant Host
    participant Sync
    participant Policy
    participant Volunteer
    Host->>Sync: Conditions, policy and authorized replica batch
    Sync->>Policy: Check opt-in, Wi-Fi/charging, allocation/time/bytes
    alt disabled or constraints unavailable
        Policy-->>Sync: Skip optional work, no content requests
    else eligible and remaining budget
        Sync->>Sync: Verify distinct owners, complete manifests, hashes, leases and limits
        Sync->>Volunteer: Directed signed profile and verified blob/lease
        alt durable accepted replica
            Volunteer-->>Sync: Real acknowledgement
            Sync->>Sync: Count confirmed copy
        else unavailable, full or invalid
            Volunteer-->>Sync: Typed failure
            Sync->>Sync: Partial/deferred, no invented success
        end
    end
    Sync->>Volunteer: Close session sockets at window end
```

## Sequence 6: Cancellation and recovery

Rust target commits per item and returns boundedly.

```mermaid
sequenceDiagram
    participant OS
    participant Host
    participant Sync
    participant Peer
    participant DB
    Sync->>DB: Commit verified item A and pending event
    Sync->>Peer: Await next bounded transfer
    OS->>Host: Expiration or worker cancellation
    Host->>Sync: CancellationToken.cancel
    Sync->>Peer: Drop requests and close swarm
    Sync->>DB: Preserve committed checkpoint, no half transaction
    Sync-->>Host: Cancelled report with committed counts
    Note over Host: Later OS window or foreground open
    Host->>Sync: Restore existing keys and run same operation
    Sync->>DB: Read checkpoint and pending outbox
    Sync->>Peer: Resume/retry idempotently
    alt crash after native post before ack
        Host->>Host: Repost same stable OS notification id
    else acknowledged
        DB-->>Host: Do not recreate old event
    end
```

## Sequence 7: Stable volunteer restart

Rust filesystem-protected transport store target.

```mermaid
sequenceDiagram
    participant Operator
    participant Store as NodeIdentityStore
    participant Disk
    participant Node
    Operator->>Store: First start, explicit protected mode
    Store->>Disk: Atomic create if absent with exclusive lock
    Store-->>Node: Transport identity, PeerId X
    Node->>Node: Serve authorized persisted content
    Operator->>Node: Shutdown or process termination
    Node->>Disk: Release identity lock, SQLite durable
    Operator->>Store: Second startup with same data directory
    alt valid protected identity file
        Store->>Disk: Open exact stored transport key
        Store-->>Node: Same PeerId X and existing data
    else corrupt, locked or inaccessible
        Store-->>Operator: Explicit failure, no replacement
    end
```
