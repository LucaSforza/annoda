# Verified local notification outbox (M2)

Authority for notification events; Rust never displays OS notifications or depends on Firebase/APNs. `NotificationEvent` exposes only stable opaque event_id and kind NewLike/NewMatch. Never include peer id, name, credential, ciphertext, contact handle or photograph in notification metadata.

New authenticated positive intent creates NewLike unless rejected/blocked. Transition into Matched creates NewMatch; each participant's event id is owner-scoped and deterministic from authenticated evidence. A newly received reciprocal like may produce both types; native UI may group them. A local reciprocal like also creates its owner's NewMatch. No duplicate event is created on repeated delivery. Unsupported/invalid/revoked/expired input never creates events.

Short SQLite transactions commit match/like state, replay marker, outbox event and sync checkpoint together. Existing M1 public methods keep their return types; implementation can add internal transaction helpers and append schema tables without dropping old data. Contacts persist privately after existing match gate but do not create a notification kind in M2. Per-owner settings control likes/matches independently. Disabled settings suppress new events, not domain state; pending reads must respect current preferences. Returning an event never marks it delivered/displayed.

Outbox has Pending/Acknowledged-by-host states and unique stable ids. `pending_notifications(owner, limit)` is bounded and replayable across crashes. `acknowledge(owner, event_id)` is explicit and idempotent; unknown/wrong-owner ids cannot acknowledge another owner's event. Ack means adapter acknowledged handling, not a verified human view. Durable uniqueness plus processed-message evidence prevents a new event after ack on unchanged mailboxes. Never delete network parcels merely because an event was returned.

SyncReport returns newly created events only; native hosts must also drain durable pending events to recover from a prior process crash. Thus no new activity means no newly created report events, while a separate pending read may legitimately retry old unacknowledged work. Native platform notification identifiers must derive from event_id so crash after posting but before ack can coalesce retries. Exactly-once visible display cannot be guaranteed; OS permissions/user suppression/termination can prevent display even after successful local request submission. Persist preferences and ack state; keep metadata minimal and expose no unauthenticated notification shortcut.

Bounds apply to pending reads/outbox storage: at most 4096 pending events and 8192 total retained rows per owner. Oldest acknowledged entries may be pruned to retain this bound; replay evidence and one-way match transitions still prevent notification recreation. Reaching a local capacity limit returns explicit deferred/storage error with transaction rollback; do not commit intent and lose its enabled event. Replay markers remain sufficient through message expiry and future cleanup must not resurrect old acknowledged events. Sensitive database state remains unencrypted in this prototype; key-vault encryption does not encrypt SQLite.
