# Distributed storage

BLAKE3 hashes normalized photo bytes. Signed owner profile references PhotoManifest entries; hash alone authenticates bytes, not ownership or safety. Volunteer persists blobs under owner-authorized ContentLease and configured quotas; no public DHT binary values. Upload verifies length, hash, owner authorization and bounded lease before durable acknowledgement. [Protocol limits](protocol.md) apply.

Replication target counts independent providers. Client deposits to configured volunteers and advertises providers through Kademlia. Missing/corrupt provider causes fallback; repair republishes from a verified remaining copy. Copies persist while valid leases and available volunteers remain. No permanent durability guarantee. First milestone must demonstrate multiple real local swarms; periodic repair scheduler and adversarial provider discovery may be explicit planned work.

Lease validity: issued ≤ now < expires, bounded by profile/credential expiration and local maximum. Duplicate uploads consume no extra blob bytes or extend unauthorized leases. Shared content needs separate owner leases; deletion removes only that owner's authorization. Reads enforce expiry immediately; periodic garbage collection reclaims unreachable files/rows. Volunteer runtime runs cleanup on startup and every 60 seconds with skipped missed ticks; reads enforce expiry independently. SQLite free pages/WAL are not guaranteed secure erasure or physical disk shrinkage. Enforce capacity before writes atomically; account mailbox and profiles as well as photos. Bandwidth and per-peer rates need separate bounds.

Deletion: owner signs monotonically ordered tombstone for profile/photo reference; compliant volunteers cease serving that ownership and expire leases. Reject stale resurrection. Tombstone must outlive maximum stale record lifetime. Untrusted downloaders may retain and redistribute public photographs indefinitely; global deletion is impossible. [Deletion sequence](uml/sequences.md) distinguishes prototype and planned propagation.

Mailbox storage retains opaque recipient-sealed parcels containing signed envelopes until expiry, quota or authorized recipient acknowledgement. Fetch and destructive ack require recipient proof of possession. Never delete on unauthenticated poll or failed decryption. Delivered likes and replay markers persist locally through envelope lifetime. SQLite transactions couple state, deduplication and inbox visibility. Secrets are memory-only or encrypted; [privacy](privacy.md) governs retention.

## Planned repair adapter

`ReplicaRepair::repair(owner, hash, target, now) -> RepairReport` should report distinct confirmed providers, remaining deficit and typed provider errors. A future fetchable `StoredReplica` bundle includes signed profile/manifest, original signed owner lease and verified bytes, allowing volunteers to forward authorization without possessing owner keys. Repair must never extend original lease expiry. A jittered scheduler persists provider observations and retries boundedly with backoff/diverse peers. Initial directed replication helper alone is not that scheduler. Renewal requires new owner authorization and active renewed profile; offline repair cannot create it.

M2 adds compatible SQLite tables for [notification events](notifications.md) and [sync checkpoints](background-sync.md). Existing M1 records remain readable. No key bytes enter SQLite. Core event/checkpoint transactions must finish before another network await. Separate node transport files use the explicitly documented filesystem-protected mode in [key management](key-management.md).

## Application persistence

[Durable operations](durable-operations.md) specifies additive local operation, credential, discovery, report and preference records. These do not change the volunteer wire/storage authorization rules. Application publication persists its normalized content and signed leases before requesting replicas, then checkpoints real per-peer/item acknowledgements. Partial remote publication remains pending and inspectable. Superseded revisions cannot be replayed as active updates. Distributed deletion/repair are deferred; the application must return Unsupported for a global deletion promise it cannot fulfill.
